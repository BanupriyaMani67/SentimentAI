# 💬 SentimentAI — End-to-End ML Deployment

Train a sentiment classifier, serve it with **FastAPI**, put a **Streamlit** website on top, containerize with **Docker**, and deploy both services on **Render**.

> **Capstone project** · Python · scikit-learn · FastAPI · Streamlit · Docker · Render

## 1. Problem statement
Given a piece of text, decide whether its sentiment is **positive** or **negative**, and make that prediction available to anyone through a public web app.

## 2. Features
- TF-IDF + Logistic Regression model with saved (Joblib) artifacts
- REST API: `GET /`, `GET /health`, `POST /predict` (validated with Pydantic)
- Streamlit UI: examples, clear button, spinner, confidence bar, friendly errors
- 19 automated tests (pytest)
- Docker images for backend and frontend, plus `docker-compose.yml`
- Render deployment with `/health` health check

## 3. Architecture
```
 User ──► Streamlit (frontend, :8501) ──HTTP/JSON──► FastAPI (backend, :8000)
                                                        │ loads at startup
                                                        ▼
                                      tfidf_vectorizer.joblib + sentiment_model.joblib
```
The frontend never loads the model; it only calls the API (`API_URL` env var).

## 5. Dataset — read this honestly
`model/train.csv` is a **synthetic DEMO dataset** (1,200 template-based sentences, balanced), generated by `train_model.py`.
- ✅ Lets the whole pipeline run offline.
- ❌ Test accuracy (~98%) is **inflated**: sentences are built from the same templates, so train and test look alike. It is **not** production quality and will fail on real tweets, sarcasm, slang, or mixed sentiment.

**Use a real dataset (recommended for your portfolio):** Sentiment140 (1.6M tweets) on Kaggle — search "Sentiment140 dataset" → download `training.1600000.processed.noemoticon.csv`. Then convert a sample (PowerShell, venv active):
```powershell
python -c "import pandas as pd; df=pd.read_csv('training.1600000.processed.noemoticon.csv', encoding='latin-1', header=None, names=['label','id','date','query','user','text']); df=df.groupby('label').sample(20000, random_state=42)[['text','label']]; df.to_csv('model/real_train.csv', index=False)"
python model/train_model.py --data model/real_train.csv
```
(Labels `0` → negative, `4` → positive are handled automatically.) Don't commit large CSVs; add them to `.gitignore`.

## 8. API documentation
| Method | Path | Purpose |
|---|---|---|
| GET | `/` | API info and endpoint list |
| GET | `/health` | `200` if model loaded, `503` otherwise |
| POST | `/predict` | Predict sentiment |

```json
// POST /predict  request
{ "text": "This product is excellent and I love it." }
// response (real values come from the model)
{ "text": "...", "sentiment": "positive", "confidence": 0.79,
  "probabilities": { "negative": 0.21, "positive": 0.79 } }
```
Errors: `422` (empty/invalid text, with a readable `detail`), `503` (model not loaded), `500` (internal error).

### Test with Postman
1. **New → HTTP request** · method `GET` · URL `http://localhost:8000/health` · **Send** → expect `200` and `"model_loaded": true`.
2. New request · method `POST` · URL `http://localhost:8000/predict` · tab **Body → raw → JSON** (not Text) · paste the request JSON above · **Send** → expect `200` with `sentiment`.
3. Try `{"text": "   "}` → expect `422`.

PowerShell alternative:
```powershell
Invoke-RestMethod http://localhost:8000/health
Invoke-RestMethod -Method Post -Uri http://localhost:8000/predict -ContentType "application/json" -Body '{"text":"I love it"}'
```

## 9. Docker
Install Docker Desktop (WSL2 backend) and make sure it is running.

**Backend only**
```powershell
docker build -t sentimentai-api .
docker run --rm -p 8000:8000 sentimentai-api
# new terminal:
Invoke-RestMethod http://localhost:8000/health
```
**Both services (recommended)** — API on `8000`, frontend on `8501`:
```powershell
docker compose up --build
```
Open http://localhost:8501. Stop with `Ctrl+C`, then `docker compose down`.

The model is trained **during the image build**, so artifacts always match the installed scikit-learn version. Inside Docker the frontend reaches the API at `http://api:8000` (service name), not `localhost`.

## 11. Deploy on Render
> Render's UI and free-tier rules change. Verify the steps and limits at https://render.com/docs before relying on them. Free web services spin down after inactivity (first request can take ~1 minute) and may have monthly usage limits.

### A. Backend (FastAPI)
1. Sign in to Render with GitHub → **New → Web Service** → pick your repo.
2. **Language/Runtime:** Docker · **Dockerfile Path:** `./Dockerfile` · **Instance type:** Free.
3. Open **Advanced → Health Check Path:** `/health`.
4. **Create Web Service**. Wait for the build (it trains the model) until it shows **Live**.
5. Test `https://<your-api>.onrender.com/health` and `/docs`.

### B. Frontend (Streamlit) — a separate service
1. **New → Web Service** → same repo.
2. **Runtime:** Docker · **Dockerfile Path:** `./Dockerfile.frontend`.
3. **Environment variables:** `API_URL` = your backend URL (include `https://`), `API_TIMEOUT` = `90`.
4. Create it, open its URL, enter text, click **Analyze Sentiment**.

`render.yaml` is an optional Blueprint for creating both at once (replace the `API_URL` placeholder first).

### C. Troubleshooting
| Problem | Fix |
|---|---|
| Build fails on `pip install` | Check Python base image (3.12) and package pins in `requirements*.txt` |
| `/health` returns 503 | Artifacts failed to load — check logs; ensure `model/train_model.py` and `model/train.csv` are committed so the Docker build can train |
| "Port scan timeout"/no open port | App must bind `0.0.0.0:$PORT` — the Dockerfiles already do |
| Frontend says "Cannot reach the backend" | `API_URL` wrong or missing `https://`; backend asleep or failed |
| First request very slow/times out | Free tier wake-up; raise `API_TIMEOUT` and retry |
| Works locally, not in Docker | Use `http://api:8000` inside compose, not `localhost` |
